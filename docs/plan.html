Why it looks like this

Each app is a complete Godot project. You can open apps/checklist in the editor on its own, and it exports with its own package ID and icon. An AI session working on one app never touches another.

addons/ is filled, never committed. install.py puts the pinned gd-chime there, and later the factory's own services too. Deleting the folder and running install again gives the same result, which keeps copies from drifting apart.

No central registry. CI finds apps by listing apps/*/factory.json, so adding an app doesn't mean editing a shared file.

Amber marks generated content that you never edit by hand.

Which way dependencies point

Arrows mean "depends on". Nothing points back up. gd-chime stays outside the factory and never learns it exists.

How gd-chime reaches an app

The first link is already live. You approved the mirror, and its first sync is 1f5e9a6.

The pin

One small file at the root lists each outside dependency with an exact commit. To upgrade gd-chime, you change that commit, CI runs, and the change goes in only if it passes.

install.py fetches that exact commit with git, keeps a copy in .cache/, and copies only addons/gd_chime/ into each app. gd-chime's demos, tests and checks stay out. Apps use only what gd-chime's facade exports, as its constitution requires.

{
  "gd_chime": {
    "repo":   "https://github.com/latent-sea/gd-chime",
    "commit": "1f5e9a6…",
    "copy":   "addons/gd_chime"
  }
}

The Checklist app

Deliberately small. The point is the path, but it's still a real app that stays on your phone and keeps what you put in it.

What it does

AddType in the field and press Enter (gd-chime's field).
TickTap a row to mark it done, or tap again to undo.
DeleteSwipe a row, or use its menu (SwipeRow). You're never forced to swipe.
Clear doneRemoves all ticked items at once. It's refused, with a reason, when nothing is ticked.
KeepSaved to user://checklist.json after every change and loaded at start.

Out of scope for milestone 1: multiple lists, reminders, sync, sharing and settings.

How it's built

gd-chime's own rules: a model holds each fact, a press is a command sent to the model, and the screen only draws.

Build pipeline

One workflow, .github/workflows/ci.yml, runs on every push to the branch and on pull requests. It checks first and builds second.

The steps, in order

Each step ends with something you can check. The order matters: every step builds on the one before it.

  1. 0

    Publish gd-chime as a public mirror

    Done

    The monorepo's mirror Action publishes snapshot commits to latent-sea/gd-chime. The first sync is 1f5e9a6, readable without logging in.

  2. 1

    Pin and install gd-chime

    NextClaude

    dependencies.json plus tooling/install.py, written in Python using only its standard library. It fetches the pinned commit, caches it, and copies addons/gd_chime into each app. Tests check that running it twice gives the same result, that nothing outside addons/ is copied, and that a bad pin gives a clear error.

    Done when: on a clean checkout, python tooling/install.py runs, and running it again changes nothing.

  3. 2

    Checklist app skeleton

    PlannedClaude

    apps/checklist/ gets a Godot 4.6 project using the Mobile renderer and gd-chime's three required settings. The root node is a ChimeApp with its own palette. factory.json holds the name and package ID.

    Done when: it opens in the editor with no errors, and --probe prints PROBE OK headless.

  4. 3

    Checklist behaviour and saving

    PlannedClaude

    Add, tick, delete and clear done, with saving to user://. There are unit tests for the model and the store, and the probe walks every action.

    Done when: all tests pass, and items survive quitting and reopening on desktop.

  5. 4

    CI: the check job

    PlannedClaude

    The workflow installs Godot 4.6, runs the tooling tests, runs install, imports the app, runs the unit tests and runs the probe. It finds apps by listing apps/*/factory.json.

    Done when: it's green on GitHub, and breaking a test on purpose turns it red.

  6. 5

    CI: debug APK

    PlannedClaude

    An export preset for com.latentsea.checklist (arm64), a shared debug keystore, and a second job that exports the APK and attaches it to the run.

    Done when: every green run has a checklist-debug.apk to download.

  7. 6

    Install it on your phone

    PlannedYou

    Download the APK, allow installs from this source, and install. I'll give you a short list of things to try: add, tick, swipe, rotate, close and reopen. This is the first time gd-chime runs on a real phone.

    Done when: it installs, works, and your items are still there after you restart the app.

  8. 7

    PlannedClaude

    A short list of every hand step it took to make this app, and how long each took. That list is what shapes step 8.

  9. 8

    PlannedClaude

    Probably a tooling/create_app.py <name> that creates a new app's project, factory.json and export preset. The exact list comes from step 7.

Decision records

Written to docs/decisions/, each a few paragraphs long. Each card ends with what would make us reconsider.

D-001

gd-chime comes from a pinned commit of a public mirror

The mirror publishes snapshots, so no monorepo history leaks. The factory's pin makes every build reproducible, and upgrades happen on purpose.

Reconsider if gd-chime moves to its own repo, or starts publishing tagged releases.

D-002

One Godot project per app

Each app has its own export identity, icon and settings, and parallel AI sessions don't conflict. The cost is one copy of the addons per app, which is gitignored and cheap.

Reconsider if apps start needing to share scenes at runtime.

D-003

Persistence stays in the app until a second app needs it

We build real behaviour first and extract the shared part afterwards, as the README says: prove abstractions through applications.

Reconsider when a second app needs local saving, which is likely.

D-004

Apps define their own look through gd-chime's exported Themes

gd-chime's material look lives in its demo folder, which isn't part of its public API. The app builds a palette through GdChime.Themes and doesn't copy demo code.

Reconsider if gd-chime starts shipping ready-made looks in the addon.

D-005

Milestone 1 ships debug APKs, with a shared debug key in the repo

A debug key can't publish anything, and keeping one fixed means each new APK installs over the last without an uninstall. Release keys will never go in the repo.

Reconsider at milestone 2, when release signing arrives.

D-006

Factory tooling is Python 3, standard library only

It runs on Windows, in CI and in cloud sessions, with nothing to install through pip. The alternative is GDScript tools run by headless Godot.

Reconsider if you'd rather not install Python on Windows. See the question at the end.

Risks

What could go wrong, and when we'll find out.

Could block the milestoneCould cost timeMinor

gd-chime hasn't run on a real phone yet

gd-chime expects a 1920×1080 base with stretch disabled, and its mobile demo only runs in a phone-shaped desktop window. Text or touch targets could come out the wrong size on a real screen. We find out at step 6. If it's broken, the fix probably belongs in gd-chime rather than here, and I'll bring it to you first.

gd-chime is tested on Forward+, but phones need the Mobile renderer

gd-chime's projects declare Forward+. The Checklist will use Mobile, which is the right choice for Android. We find out at step 2, because the probe runs under Mobile from the start.

Heavy CI downloads

Godot export templates are large. Caching them by version keeps runs fast after the first.

The mirror falls behind the monorepo

This is intended. Apps only see gd-chime changes when the pin moves, so nothing changes under them unexpectedly.

Runner image changes

ubuntu-latest moves to Ubuntu 26 on 19 October. CI pins ubuntu-24.04.
